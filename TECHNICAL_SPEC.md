# TECHNICAL SPECIFICATION: Profile Page Overhaul

## 1. Overview
This specification details the structural and visual refactoring of `profile.html` to ensure layout consistency, component reuse, and zero overlap between UI elements. We are migrating from ad-hoc inline styles to a centralized CSS-driven architecture.

## 2. Impacted Components

### 2.1 Frontend: Profile Structure (`frontend/profile.html`)
*   **Refactoring**: 
    *   Remove all `style="..."` attributes.
    *   Standardize the `.profile-container` to match the main app's vertical rhythm.
    *   Ensure `.profile-header` and `.profile-grid` use a consistent gap (2rem).
*   **Actions**:
    *   Map all buttons to `btn-primary`, `btn-secondary`, or `btn-danger-minimal`.
    *   Update tab buttons to use a shared `.tab-nav` component structure.
    *   Standardize the `file-input` trigger to match the `btn-primary` aesthetic.

### 2.2 Frontend: Styling (`frontend/index.css`)
*   **New Design Tokens/Utilities**:
    *   `.profile-page`: Global wrapper class for profile-specific layout rules.
    *   `.profile-grid`: A two-column layout for desktop (Sidebar + Main) and single column for mobile.
    *   `.profile-card`: A specialized version of `.glass-panel` with consistent padding (`2rem`) and border-radius (`24px`).
*   **Grid Consistency**:
    *   `.mini-grid`: Define as a responsive grid using `repeat(auto-fill, minmax(160px, 1fr))` to prevent overlapping and ensure David's (Persona) desktop scaling needs.
    *   `.mini-book-card`: Standardize margins, padding, and hover effects to match the main catalog's "tactile" feel.
*   **Collision Prevention**:
    *   Set strict `z-index` hierarchy:
        *   Modals: `10000`
        *   `top-nav-island`: `1000`
        *   `profile-header`: `1` (ensures it scrolls UNDER the nav island).
    *   Adjust `.profile-container` padding: `padding-top: 120px` to clear the fixed island safely.

### 2.3 Frontend: Translations (`frontend/translations.js`)
*   **Verification**: Ensure `memberId`, `joinDate`, and `availableCredits` are used consistently.
*   **New Keys**: Add `emptyLibrary` and `emptyUploads` messages if needed for better UX.
